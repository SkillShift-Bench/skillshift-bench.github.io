# `submissions/`

One JSON file per leaderboard entry. Everything here is generated by
`skillshift report` and checked by `skillshift validate`; nothing is written by
hand.

## Naming

```
YYYY-MM-DD--<method>--<model>.json
YYYY-MM-DD--<method>--<model>.receipt.json     (required for self-reported entries)
```

| part | rule |
| --- | --- |
| `YYYY-MM-DD` | the run date. **Must equal `submission.date` inside the file.** |
| `<method>` | lower-case `a-z`, `0-9`, `-` and `.`; no `--` |
| `<model>` | same character set; `--` is the field separator |

The receipt filename is the results filename with `.json` replaced by
`.receipt.json`. CI derives it, so it must match exactly.

Examples:

```
2026-08-23--awm--mixed.json
2026-09-01--mpcr-full--gpt-5-mini.json
2026-09-01--mpcr-full--gpt-5-mini.receipt.json
```

`mixed` is the slug used for the launch entries transcribed from Table 1, which
pools three backbones.

## What a pull request may contain

**Yes**

- one `*.json` results file
- its `*.receipt.json`, if the entry is `self-reported`

**No**

- `per_task.jsonl`, trajectories, screenshots, or logs — SkillShift-Bench
  publishes aggregate numbers only. The receipt already commits to your
  per-task vector by SHA-256; keep that file locally in case an entry is
  disputed.
- edits to somebody else's entry

## The five checks

Every pull request runs
[`skillshift validate`](https://github.com/SkillShift-Bench/skillshift-bench/blob/main/src/skillshift/eval/validate.py)
— the same code you can run locally before opening it.

1. **Schema** — the file matches `results.schema.json` (and the receipt matches
   `receipt.schema.json`).
2. **Coverage** — all ten slots are present for all four metrics. A value that
   was not measured is an explicit `null` **with an entry in `reasons`**, never
   a `0`.
3. **Denominators** — `n.websites` is GitLab 162 / Magento 114 / WordPress 79,
   every `n.conditions` is 355, and each metric's overall value is the
   unweighted mean of the eighteen underlying cells (tolerance 0.02, which is
   what two printed decimals allow). This is the check that catches a mistyped
   number now that per-task data is not published.
4. **Ranges** — `SR, SFR ∈ [0,100]`, `AS > 0`, `ASC ≥ 0`; an SFR value resting
   on fewer than 30 skill invocations is flagged low-confidence.
5. **Receipt** — a `self-reported` entry must ship one; its `harness_version`
   must be supported, its `n_per_cell` must be the official counts, its
   `aggregate` must match the submitted numbers verbatim, and its `env_digests`
   must match the published environment images.

**Check 5's digest comparison is currently lenient.** The environment images
are not published yet, so `skillshift-envs/DIGESTS.json` holds `null` for every
key and there is nothing to compare against. The workflow says so explicitly on
every run rather than reporting a pass it did not earn; it tightens on its own
as soon as real digests land. See the `Decide digest strictness` step in
[`../.github/workflows/validate-submission.yml`](../.github/workflows/validate-submission.yml).

Run all of it locally first:

```bash
make check
```

## Disputes

If an entry is questioned, the maintainers may ask the submitter **privately**
for that run's `per_task.jsonl`, to hash against the published
`per_task_commitment`. The file is used for verification only and is never
published. An entry whose submitter declines is marked `unverifiable` or
removed. See `docs/results-policy.md` §"Disputes" in the main repository.
